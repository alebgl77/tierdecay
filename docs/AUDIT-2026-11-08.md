# Coherence audit — 8 November 2026

The review found real inconsistencies between the engine, CLI, MCP tools,
exports and adapter instructions. The changes in this branch address those
cases and add regression coverage. A dependency graph is evidence for where
to look; it is not proof that every agent integration works in production.

Base reviewed: `b836dad635c39fb2ff6bafbe8f7ffdb33c223dec`.

## Findings and changes

| Finding | Previous behavior | Result |
|---|---|---|
| Known risk-3 class | `route` required T3 while `status` and routing exports could suggest a lower probe or recertification tier | Status and all routing-table formats retain T3, including after an epoch change |
| Fresh installation | CLI implicitly selected shadow and required an economic config; MCP selected legacy without that config | Both interfaces default to legacy without config and shadow with config; explicit policies remain available |
| Standalone MCP rubric | The tool bypassed the request validator and could score malformed input | Shared validation rejects missing, extra, non-integer and out-of-range axes |
| Export ownership | A same-name manual skill could be overwritten; stale generated directories could be removed with user-added content | Every destination is checked before writing; only owned generated instructions are removed, preserving sibling files |
| Concurrent installation | CI reproduced two installers entering the directory lock together on Ubuntu; manifest rename errors could then be masked by Bash conditional calls | Exclusive file creation replaces the directory mutex, staging uses a private temporary directory, and manifest commit failures are explicit |
| In-memory class ambiguity | Different surfaces independently selected entries | Status and MCP lookup use the route resolver; exports validate the state too. The persisted Markdown parser already rejected duplicate classes |
| Adapter precedence | Several prompts omitted safety/quarantine or described a different order | Safety, quarantine, epoch recertification, referenced live playbook, PRIORS, then rubric; sticky floors remain binding |
| Rubric wording | “Any axis maxed” implied a score of 2 on a two-point axis forced T3; discretionary tie-breaks also differed from code | T3 at total ≥7 or any axis scoring 3. The numeric engine thresholds are unchanged |
| Roles and permissions | T0 placement, cheap-model wording, and plugin permission claims diverged | Read-only T0 and workhorse bindings are consistent; optional plugin permission gates are described as optional |
| Public documentation | Checksum instructions omitted the SBOM covered by the manifest; historical rules looked current; deterministic/read-only claims were too broad | Download steps cover both files; historical examples are labeled; claims distinguish routing, locking, learned-state writes and exports |
| Graphics | Social cards guaranteed savings on every run; the state image suggested feedback into SPEC; the economic illustration obscured assumptions | Unified social artwork, fixed-rubric state diagram, explicit illustrative cost model, common tier colors and portable SVG arrowheads |

Canonical sources were edited first. The Claude plugin was then regenerated
with `node scripts/build-plugin.js`; its checked-in copies are not a second
implementation to maintain manually.

The installer collision was reproduced by the existing CI test and again by
the expanded five-round regression. It matches the upstream
[uutils mkdir concurrency defect](https://github.com/uutils/coreutils/issues/13970),
whose [fix](https://github.com/uutils/coreutils/commit/bf423f388d543b9180db6b7283d82b301f138913)
restores failure on concurrent non-recursive creation. The installer now uses
Bash noclobber for exclusive acquisition, so correctness does not depend on
that `mkdir` behavior. Existing directory-style locks still block acquisition.

## Graphify evidence

Download [the interactive graph](audit/graphify-2026-11-08.html) and open it in
a browser. Graph data is embedded in the HTML; its visualization library is
loaded from a version-pinned CDN with an integrity hash. Internet access is
needed for that library. GitHub displays the source rather than running it.

The structural extraction covered 102 code files. Semantic review covered
90 documentation files and 11 images, split across 16 extraction chunks.
The resulting directed graph contains **1,267 nodes, 2,199 edges and 98
communities**. Generated plugin copies are included, so these counts do not
represent independent features or an architectural quality score.

The strongest structural hubs include `parseLedger`, the CLI entry point,
`replay`, `route`, and `doctor`. Traversal from `route` connects CLI, MCP,
replay, state parsing, exports and regression suites. That guided the
cross-interface checks in [test-coherence.js](../tests/test-coherence.js).
The shared resolver now also serves status and MCP playbook lookup.

Graph limitations are retained rather than interpreted as product defects:

- This is an audit snapshot collected during review, with baseline AST and
  semantic/visual extraction during the edits. It is not a final-commit index;
  line numbers and some descriptions precede the fixes.
- 24 files were outside Graphify's detected formats, notably TOML, JSONL and
  extensionless files. Adapter tests and configuration parsing cover relevant
  configuration separately.
- Extraction diagnostics found 19 unresolved internal symbol endpoints,
  corresponding to exported constants such as `VERSION` and `CLASS_RE`, plus
  116 external-reference edges. These are extractor-resolution limits, not
  evidence of broken Node imports.
- The directed graph merges some relations sharing the same endpoints;
  diagnostics counted 140 such candidate edge collapses. It must not be used
  as an exhaustive call trace.
- Host token accounting was unavailable. No token-cost or efficiency claim
  is inferred from placeholder zero counters.

The Bash installer/guard suites could not run in the restricted local Windows
environment. That host also refused junction creation, so the dangling-link
export subcase is skipped locally and remains mandatory in CI.
The PR's existing Linux, macOS and Windows CI matrix remains the
authority for those checks and for container/action integration. Consult the
PR checks for their actual result; this report does not predeclare CI success.

Live end-to-end sessions in Claude Code, Codex, Antigravity and the other
agent clients were not executed. Configuration validity and repository tests
do not prove those clients will honor every instruction or permission in a
specific installed version.

## Remaining product validation

1. Run a real installation and one routed/verified task in each supported
   client before declaring its integration production-validated.
2. Extend the measured pilot with held-out task classes and paired cold/warm
   runs. The current fixture validation proves the grader distinguishes its
   reference implementations; it does not establish universal savings.
3. Keep cross-interface contracts and generated-file checks in CI. Repeated
   prose across ten adapters remains a drift risk requiring review when the
   protocol changes.
